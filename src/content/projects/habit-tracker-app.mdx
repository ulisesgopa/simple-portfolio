## Overview

**Habit Flow** is a cross-platform productivity app built around a simple observation: most habit trackers assume your brain works the same way every day. They don't. Habit Flow was built for the users those apps leave behind — people who need structure, positive reinforcement, and flexibility in the same tool.

The app runs on **web, iOS, and Android** from a single TypeScript codebase using React Native and Expo Router. The web version is live and the mobile app runs on Expo Go while native packages are in progress.

---

## Role
**Solo Developer**: product design, frontend (web + native), state management, backend API, and deployment.

---

## The Problem

Existing habit tracking apps fail a specific type of user by:
- Showing too much at once (cognitive overload on bad days)
- Offering streaks as the only motivation mechanism — brutal when broken
- Being purely task-based with no emotional engagement
- Treating finances, tasks, and habits as separate apps entirely

The result: users who need the app most are the ones who abandon it first.

---

## Solution

A unified productivity dashboard where completing habits earns XP, unlocks levels and achievements, and accumulates points redeemable in a personal reward store. All modules live in one app, not six.

### Tech Stack

| Layer | Technology |
|-------|-----------|
| Mobile | React Native + Expo SDK |
| Routing | Expo Router (file-based, same model as Next.js) |
| Web | Expo web export, deployed to Vercel |
| State | Zustand + persist middleware |
| Backend | Bun + TypeScript REST API |
| Database | PostgreSQL via Prisma ORM |
| Local storage | Async Storage |

### Key Modules

1. **Habits** — Daily and weekly tracking with completion rates, streaks, and visual progress
2. **Missions (To-dos)** — Priority task management with urgency classification
3. **Finances** — Income and expense tracker with monthly summaries and balance tracking
4. **Calendar** — Personal event scheduling with weekly and monthly views
5. **Rewards Store** — Spend earned XP on real personal rewards defined by the user
6. **Battle Mode** — Extreme focus session that visually locks distractions and counts down

### Gamification System

- XP earned for every completed action
- Level progression system
- Achievement badges for milestones
- Reward store redeemable with accumulated points

### Accessibility — Built as Core Features

Every accessibility option is a first-class feature, not a checkbox:
- **Low-stim mode** — reduces animations and visual noise for high-sensitivity days
- **Dyslexia-friendly font** — toggleable OpenDyslexic or similar
- **High contrast mode** — for visual processing needs
- Full keyboard navigation on web

## Technical Decisions Worth Explaining

**Why Expo Router over React Navigation?**
File-based routing gives the same mental model as Next.js on both mobile and web. The same directory structure defines routes on iOS, Android, and the browser — no separate router configuration per platform. Deep linking works out of the box.

**Why Zustand with Async Storage persistence?**
The app has rich local state: current XP, active habits, theme, accessibility flags, pending sync queue. Zustand's `persist` middleware serializes the store to Async Storage on every update and rehydrates on mount, in four lines of code. Redux would have required actions, reducers, and a custom persistence layer.

**Why a Bun backend instead of serverless functions?**
The backend handles sync logic, XP calculation, and cross-device state persistence — operations that benefit from stateful process context and fast startup times. Bun runs TypeScript natively without a build step, starts in milliseconds, and performs well under sustained load. Prisma provides type-safe queries and schema migrations.

## Challenges

1. **Offline-first architecture** — local Async Storage state needs to sync with PostgreSQL without conflicts when connectivity is restored. Implemented an optimistic update model with a sync queue.

2. **Cross-platform styling** — Tailwind CSS on web, React Native StyleSheet on mobile. Built a component abstraction that accepts styled variants for each platform without exposing the difference to the feature layer.

3. **Accessibility and gamification together** — level-up animations and XP celebrations must respect low-stim mode. Any motion or sound effect that fires on a habit completion checks the user's preference first.

## Final Thoughts

This is the most personal project in the portfolio. I'm building for a problem I experience myself — and that changes how you make product decisions. There's no "the user will figure it out" shortcut when you are the user.

It's also the project that forced the most breadth: React Native for mobile, Expo for cross-platform tooling, a real backend with sync logic, and accessibility engineering as a design constraint. Every decision has a personal reason behind it, not just a technical one.
