## Overview

**Habit Tracker App** is a mobile-first application built for people who want to manage their daily life through a system that feels like a video game. It targets neurodivergent users specifically — people who struggle with traditional habit apps that feel clinical, repetitive, or overwhelming.

The app runs on **iOS, Android, and Web** from a single codebase using React Native and Expo Router.

---

## Role
**Solo Developer** — architecture, UI, state management, backend API, and deployment.

---

## The Problem

Most habit tracking apps fail neurodivergent users because they:
- Show too much information at once (cognitive overload)
- Have no motivation system beyond streaks
- Offer no offline capability
- Are purely task-based with no emotional engagement

---

## Solution

A gamified dashboard where completing habits earns XP, unlocks levels and achievements, and accumulates points redeemable in a reward store. All wrapped in a UI with strong accessibility controls.

### Tech Stack

| Layer | Technology |
|-------|-----------|
| Mobile | React Native + Expo SDK |
| Routing | Expo Router (file-based, like Next.js) |
| Web | Expo web export (static) |
| State | Zustand |
| Backend | Vercel serverless functions |
| Database | PostgreSQL via Prisma ORM |
| Local storage | Async Storage |
| Styling | TailwindCSS (web) + React Native StyleSheet |

### Key Modules

1. **Habits** — Daily/weekly habit tracking with streaks and completion rates
2. **Missions (To-dos)** — Priority task management
3. **Finances** — Income/expense tracker with monthly summaries
4. **Calendar** — Local event scheduling with weekly/monthly views
5. **Rewards Store** — Spend XP on personal rewards
6. **Battle Mode** — Extreme focus session that locks distractions

### Gamification System

- XP earned for every completed action
- Level progression system
- Achievement badges
- Reward redemption store

### Accessibility Features

Built as first-class features, not afterthoughts:
- **Low-stim mode** — reduces animations and visual noise
- **Dyslexia-friendly font** option
- **High contrast mode**
- Full keyboard navigation on web

## Technical Decisions Worth Explaining

**Why Expo Router instead of React Navigation?**
File-based routing means the same mental model as Next.js. The web version shares the same route structure as mobile — no separate router config per platform.

**Why Zustand over Redux?**
The app has rich local state (current XP, active habits, theme, accessibility flags) but no complex server-state caching needs. Zustand handles this with significantly less boilerplate than Redux, and integrates with Async Storage for persistence in a few lines.

**Why Prisma on the backend?**
Schema migrations and type-safe queries reduce bugs when adding modules. The same TypeScript types generated by Prisma are reused in the Expo frontend via shared type imports.

---

## Challenges

1. **Offline-first architecture** — synchronizing local Async Storage state with the remote PostgreSQL database without conflicts
2. **Cross-platform styling** — Tailwind works on web, React Native StyleSheet on mobile — building a component API that abstracts both
3. **Accessibility and gamification together** — making sure the reward animations and level-up sequences don't break low-stim mode users

## Final Thoughts

This project demonstrates the full lifecycle of a product from concept to deployed app on multiple platforms. It goes beyond landing pages and shows real application state management, cross-platform routing, accessibility engineering, and backend integration — all in a single codebase.
