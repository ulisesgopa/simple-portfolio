## Overview

**PeludoTag** solves a real and urgent problem: when a pet gets lost, the owner has no fast, direct way to connect with whoever finds it. Phone numbers written on collars wear off. Flyers take time. Social media posts get buried.

PeludoTag replaces all of that with a **QR code on the collar**. Anyone with a phone can scan it, see the pet's profile, and notify the owner — no app required on the finder's side.

---

## Role
**Solo Developer** — product design, frontend, backend (Supabase), QR generation, email notifications, production deployment.

---

## The Problem

Traditional lost pet solutions require:
- The finder to have the owner's phone number
- The owner to proactively post and monitor social media
- No real-time location sharing
- No way to confirm the pet was found until direct contact

---

## Solution

A web platform where:
1. Owner registers their pet with name, photo, breed, medical notes, and contact info
2. System generates a unique QR code per pet
3. Owner prints and attaches QR to collar or tag
4. Finder scans QR → sees public pet profile
5. Finder optionally shares their GPS location
6. Owner receives instant email notification via Resend

### Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | Next.js (App Router) |
| Database & Auth | Supabase (PostgreSQL + Row Level Security) |
| Email notifications | Resend API |
| QR generation | qrcode + qrcode.react |
| Animations | Framer Motion |
| Error tracking | Sentry |
| Analytics | Vercel Analytics |
| Styling | TailwindCSS 4 |

### Key Features

1. **Pet registration** — Full profile with photo upload to Supabase Storage
2. **QR code generation** — Unique per pet, downloadable as PNG
3. **Public pet profile** — Accessible without login, no app needed
4. **Location sharing** — Geolocation API on finder's browser
5. **Email alerts** — Instant notification to owner via Resend
6. **Dashboard** — Owner manages all pets, views scan history

## Final Thoughts

PeludoTag is a complete product with a clear real-world use case, production-level error handling (Sentry), real analytics, and a well-reasoned backend choice (Supabase). It shows the ability to take a feature from user problem → architecture decision → shipped product.
