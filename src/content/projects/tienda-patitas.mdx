## Overview

**Tienda Patitas** is the frontend landing page for a pet products store. Part of a larger workspace that includes a backend and a point-of-sale system, this landing serves as the public-facing entry point — presenting the brand, showcasing products, and driving users toward purchase or contact.

---

## Role
**Frontend Developer** — landing page design implementation, component architecture, and integration with the broader Tienda Patitas product ecosystem.

---

## The Problem

Pet product stores in Latin America frequently have outdated or non-mobile web presences. Customers discover products on social media but have no clean web experience to land on. The landing needed to bridge that gap: professional, fast, and mobile-first.

---

## Solution

A focused landing page built as part of the Tienda Patitas monorepo workspace, sharing type definitions and data contracts with the backend and dashboard systems.

### Tech Stack

| Layer | Technology |

| Framework | React 18 |
| Build tool | Vite |
| Language | TypeScript |
| UI components | shadcn/ui + Radix UI |
| Forms | React Hook Form + Zod |

### Key Sections

1. **Hero** — Brand statement with primary CTA
2. **Product catalog** — Category-filtered product grid
3. **Featured products** — Highlighted items with pricing
4. **About** — Brand story and trust signals
5. **Contact / WhatsApp CTA** — Direct conversion path

---

## Technical Decisions Worth Explaining

**Why part of a monorepo workspace?**
The landing, backend, and POS system for Tienda Patitas share the same product data model. A workspace structure (`tiendapatitas-workspace`) lets the frontend import shared TypeScript types directly from the backend contracts — no duplication of type definitions across projects.

**Why React Router DOM instead of Next.js?**
The landing is part of a Vite project where server-side rendering isn't required. React Router DOM provides client-side routing for the product detail pages without the Next.js overhead. Vite's build output is a static bundle, easy to deploy anywhere.

---

## Challenges

1. **Workspace integration** — Keeping the landing page types in sync with the backend data contracts while both were evolving simultaneously.
2. **Product filtering UX** — Implementing category filters that feel instant (client-side filtering via `Array.filter()`) without any visible layout shift.
3. **WhatsApp conversion flow** — Encoding product details into WhatsApp deep links so customers could initiate a purchase inquiry from a product card in one tap.

---

## Final Thoughts

Tienda Patitas demonstrates frontend work within a real product system — not an isolated landing page, but a piece of a larger architecture with shared types, a real backend, and a coordinated deployment pipeline. It reflects how professional frontend work actually functions inside a product team.
